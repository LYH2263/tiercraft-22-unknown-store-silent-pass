# 05-tiercraft（筑层）

筑层 — 数仓分层建设台：贴源入仓 → 明细清洗标准化 → 汇总落表 → 层间行数/键对账。

**不是** 多源 Feed 归并，**不是** 作业依赖编排，**不是** CDC 变更流按序落库，**不是** 质检隔离签发。
**也不是** 报表看板 / CRUD 后台 / 电商订单前台 / OA 工单。

## 启动

```bash
docker compose up --build
```

本地开发：

```bash
# 后端
cd backend
pip install -r requirements.txt
set DATA_DIR=..\data
uvicorn app.main:app --reload --port 10500

# 前端
cd frontend
npm install
npm run dev
```

| 入口 | 地址 |
| --- | --- |
| 前端 | http://localhost:5500 |
| 接口 | http://localhost:10500 |

## 主链

登记主题域 → 维护门店维 → 贴源层装载夹具 → 明细层清洗标准化（维命中校验）→ 汇总层聚合 → 层间对账报告与各层列表数字同源

## 门店维与清洗口径

- 门店维（`门店维` 页面）维护门店编码、名称、启用态。贴源到明细时，**编码必须精确命中启用维**才允许写入明细；未知编码、已停用/已删除编码一律进「维缺失拒收清单」，不写明细占位行，也不做店名模糊匹配。
- 命中启用维后店名以维表为准：贴源店名为空则用维表名称回填（标记`空名回填`）；贴源店名与维名称冲突则覆盖为维表名称（标记`异名覆盖`），冲突回填数计入任务报告，杜绝同编码多店名。
- 维停用或删除只影响**之后**的贴源到明细清洗。保存维变更不级联改写或删除历史明细；读明细不临时关联维表，明细层店名是清洗入库时的快照。
- 任务报告的输入/写入/拒收/空名回填/冲突覆盖均由贴源表、明细层、拒收清单按本次任务 SQL 同源派生，并满足「输入 = 写入 + 拒收」硬校验，不设独立计数器对账。
